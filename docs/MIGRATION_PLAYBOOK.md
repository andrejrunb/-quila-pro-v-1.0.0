# Playbook de Migração e Escalabilidade - Áquila Pro\n\n## 📋 Visão Geral\n\nEste documento fornece um guia passo-a-passo para migrar de uma arquitetura Single-Server para Multi-Tier sem downtime, com validações e rollback automático.\n\n---\n\n## 🎯 Fases de Migração\n\n### Fase 1: Planejamento (1-2 semanas)\n\n#### 1.1 Avaliação do Sistema Atual\n\n```bash\n# Coletar métricas do sistema atual\n./scripts/collect-baseline-metrics.sh\n\n# Gerar relatório de capacidade\n./scripts/capacity-report.sh\n\n# Resultado: baseline_metrics.json\n```\n\n**Checklist:**\n- [ ] Número de alunos ativos\n- [ ] Número de câmeras\n- [ ] Picos de uso (horários)\n- [ ] Taxa de crescimento esperada\n- [ ] Requisitos de uptime\n- [ ] Orçamento disponível\n\n#### 1.2 Seleção de Arquitetura\n\n```\nSe alunos <= 250:\n  → Manter Single-Server\n  → Adicionar backup automático\n  → Implementar monitoramento\n\nSe 250 < alunos <= 500:\n  → Migrar para Multi-Tier\n  → 3-5 servidores\n  → Load balancer Nginx\n  → MySQL replicado\n\nSe alunos > 500:\n  → Considerar Microserviços\n  → Kubernetes cluster\n  → Escalabilidade automática\n```\n\n#### 1.3 Dimensionamento de Hardware\n\n```bash\n# Usar calculadora de requisitos\nnode scripts/calculate-requirements.js \\\n  --students 250 \\\n  --cameras 8 \\\n  --periods 3\n\n# Resultado: hardware-spec.json\n```\n\n---\n\n### Fase 2: Preparação (1 semana)\n\n#### 2.1 Provisionar Infraestrutura\n\n```bash\n# Criar servidores de produção\nterraform apply -var=\"environment=production\"\n\n# Resultado: 3-5 servidores provisionados\n```\n\n**Servidores necessários:**\n- 1x Load Balancer (Nginx)\n- 2x Servidor de Processamento de Vídeo\n- 1x Servidor de Reconhecimento Facial\n- 1x Servidor de Banco de Dados (Master)\n- 1x Servidor de Banco de Dados (Slave/Backup)\n\n#### 2.2 Configurar Banco de Dados\n\n```bash\n# Criar banco de dados de produção\nmysql -h prod-db-master.internal < schema.sql\n\n# Configurar replicação\nmysql -h prod-db-master.internal < replication-master.sql\nmysql -h prod-db-slave.internal < replication-slave.sql\n\n# Validar replicação\n./scripts/validate-replication.sh\n```\n\n#### 2.3 Configurar Cache Distribuído\n\n```bash\n# Instalar Redis Cluster\nredis-cli --cluster create \\\n  prod-cache-1:6379 \\\n  prod-cache-2:6379 \\\n  prod-cache-3:6379\n\n# Validar cluster\nredis-cli -h prod-cache-1 cluster info\n```\n\n#### 2.4 Configurar Load Balancer\n\n```nginx\n# /etc/nginx/sites-available/aquila-pro\n\nupstream video_servers {\n  server prod-video-1:3000 weight=1;\n  server prod-video-2:3000 weight=1;\n  health_check interval=5s fails=2 passes=2;\n}\n\nupstream face_servers {\n  server prod-face-1:3001 weight=1;\n  health_check interval=5s fails=2 passes=2;\n}\n\nserver {\n  listen 80;\n  server_name aquila-pro.com.br;\n\n  location /api/video {\n    proxy_pass http://video_servers;\n    proxy_http_version 1.1;\n    proxy_set_header Upgrade $http_upgrade;\n    proxy_set_header Connection \"upgrade\";\n  }\n\n  location /api/face {\n    proxy_pass http://face_servers;\n  }\n}\n```\n\n---\n\n### Fase 3: Migração de Dados (1-2 dias)\n\n#### 3.1 Backup do Sistema Atual\n\n```bash\n# Fazer backup completo do banco de dados\nmysqldump -u root -p aquila_pro > backup-$(date +%Y%m%d).sql\n\n# Fazer backup de arquivos\ntar -czf files-backup-$(date +%Y%m%d).tar.gz /var/aquila-pro/\n\n# Verificar integridade\nmd5sum backup-*.sql > checksums.md5\n```\n\n#### 3.2 Importar Dados para Produção\n\n```bash\n# Importar banco de dados\nmysql -h prod-db-master.internal aquila_pro < backup-20260304.sql\n\n# Validar dados\n./scripts/validate-data-integrity.sh\n\n# Resultado: Todos os dados migrados com sucesso\n```\n\n#### 3.3 Sincronizar Arquivos\n\n```bash\n# Copiar arquivos para storage compartilhado\nrsync -avz /var/aquila-pro/data/ nfs://prod-storage:/aquila-pro/\n\n# Validar sincronização\nfind /var/aquila-pro/data -type f -exec md5sum {} \\; | \\\n  sort | md5sum > local.md5\n\nfind /mnt/nfs/aquila-pro -type f -exec md5sum {} \\; | \\\n  sort | md5sum > remote.md5\n\ndiff local.md5 remote.md5\n```\n\n---\n\n### Fase 4: Testes (3-5 dias)\n\n#### 4.1 Testes Funcionais\n\n```bash\n# Executar suite de testes\npnpm test:e2e --environment=production\n\n# Validar:\n# ✓ Captura de vídeo\n# ✓ Detecção de pessoas\n# ✓ Reconhecimento facial\n# ✓ Rastreamento de presença\n# ✓ Geração de alertas\n# ✓ Relatórios\n```\n\n#### 4.2 Testes de Carga\n\n```bash\n# Executar testes de carga\nnode scripts/load-testing.js \\\n  --scenario \"Escola Média (250 alunos)\" \\\n  --duration 300 \\\n  --ramp-up 60\n\n# Validar:\n# ✓ Latência < 500ms\n# ✓ CPU < 75%\n# ✓ RAM < 70%\n# ✓ Taxa de sucesso > 95%\n```\n\n#### 4.3 Testes de Failover\n\n```bash\n# Simular falha de servidor\nkill -9 $(pgrep -f \"prod-video-1\")\n\n# Validar:\n# ✓ Tráfego redirecionado automaticamente\n# ✓ Sem perda de dados\n# ✓ Sem interrupção de serviço\n\n# Recuperar servidor\nservice aquila-pro restart\n```\n\n#### 4.4 Testes de Backup/Restore\n\n```bash\n# Testar restauração de backup\nmysql -h test-db.internal aquila_pro < backup-20260304.sql\n\n# Validar dados\n./scripts/validate-data-integrity.sh\n\n# Resultado: Backup restaurado com sucesso\n```\n\n---\n\n### Fase 5: Cutover (1 dia)\n\n#### 5.1 Preparar Cutover\n\n```bash\n# Notificar usuários sobre manutenção\n./scripts/send-notification.sh \\\n  \"Manutenção programada: 22:00 - 23:00 (1 hora)\"\n\n# Aguardar fim do horário de pico\nsleep 3600\n```\n\n#### 5.2 Ativar Produção\n\n```bash\n# Atualizar DNS para apontar para load balancer\naws route53 change-resource-record-sets \\\n  --hosted-zone-id Z123456 \\\n  --change-batch file://dns-update.json\n\n# Aguardar propagação de DNS (5-10 minutos)\nsleep 600\n\n# Validar tráfego\ncurl -v https://aquila-pro.com.br/api/health\n```\n\n#### 5.3 Monitorar Cutover\n\n```bash\n# Monitorar métricas em tempo real\nwatch -n 1 'curl -s https://aquila-pro.com.br/api/metrics | jq .'\n\n# Validar:\n# ✓ Tráfego sendo processado\n# ✓ Sem erros\n# ✓ Latência normal\n# ✓ CPU/RAM dentro dos limites\n```\n\n#### 5.4 Validar Funcionalidades\n\n```bash\n# Teste manual completo\n1. Fazer login\n2. Visualizar dashboard\n3. Verificar câmeras ativas\n4. Gerar alerta manual\n5. Gerar relatório\n6. Fazer logout\n\n# Resultado: Todas as funcionalidades operando normalmente\n```\n\n---\n\n### Fase 6: Estabilização (1 semana)\n\n#### 6.1 Monitoramento Intensivo\n\n```bash\n# Monitorar 24/7 durante primeira semana\n./scripts/intensive-monitoring.sh\n\n# Alertas automáticos para:\n# - CPU > 80%\n# - RAM > 75%\n# - Latência > 1000ms\n# - Taxa de erro > 1%\n```\n\n#### 6.2 Otimizações\n\n```bash\n# Coletar dados de performance\n./scripts/collect-performance-data.sh\n\n# Analisar e otimizar\n./scripts/analyze-performance.sh > optimization-report.md\n\n# Aplicar otimizações\n# - Ajustar tamanho de cache\n# - Otimizar queries de banco de dados\n# - Ajustar pool de conexões\n```\n\n#### 6.3 Documentação\n\n```bash\n# Documentar configuração final\n./scripts/generate-documentation.sh > PRODUCTION_CONFIG.md\n\n# Criar runbooks\n./scripts/create-runbooks.sh\n\n# Treinar equipe de operações\n./scripts/schedule-training.sh\n```\n\n---\n\n## 🔄 Rollback Plan\n\nSe algo der errado durante a migração:\n\n### Rollback Automático\n\n```bash\n# Script de rollback automático\n#!/bin/bash\n\necho \"🔄 Iniciando rollback...\"\n\n# 1. Atualizar DNS para apontar de volta para sistema antigo\naws route53 change-resource-record-sets \\\n  --hosted-zone-id Z123456 \\\n  --change-batch file://dns-rollback.json\n\n# 2. Aguardar propagação de DNS\nsleep 600\n\n# 3. Validar tráfego\nif curl -f https://aquila-pro.com.br/api/health > /dev/null; then\n  echo \"✅ Rollback bem-sucedido\"\nelse\n  echo \"❌ Rollback falhou\"\n  exit 1\nfi\n\n# 4. Notificar usuários\n./scripts/send-notification.sh \"Sistema restaurado para versão anterior\"\n```\n\n### Rollback Manual\n\n```bash\n# Se o rollback automático falhar\n\n# 1. SSH no load balancer\nssh admin@prod-lb.internal\n\n# 2. Atualizar configuração Nginx\nvi /etc/nginx/sites-available/aquila-pro\n# Mudar upstream para apontar para servidor antigo\n\n# 3. Recarregar Nginx\nsudo systemctl reload nginx\n\n# 4. Validar\ncurl -v https://aquila-pro.com.br/api/health\n```\n\n---\n\n## 📊 Matriz de Decisão de Migração\n\n```\nCritério                | Single-Server | Multi-Tier | Microserviços\n────────────────────────┼───────────────┼────────────┼──────────────\nAlunos                  | ≤ 250         | 250-500    | > 500\nCâmeras                 | ≤ 5           | 8-15       | 30+\nUptime Requerido        | 99.5%         | 99.9%      | 99.99%\nTempo de Migração       | N/A           | 1-2 semanas| 2-4 semanas\nComplexidade            | ⭐            | ⭐⭐⭐    | ⭐⭐⭐⭐⭐\nCusto                   | $$$           | $$$$$      | $$$$$$\nRisco de Downtime       | Alto          | Médio      | Baixo\n```\n\n---\n\n## 🚨 Checklist de Migração\n\n### Pré-Migração\n- [ ] Aprovação de stakeholders\n- [ ] Orçamento aprovado\n- [ ] Hardware provisionado\n- [ ] Backups completos realizados\n- [ ] Plano de rollback documentado\n- [ ] Equipe treinada\n- [ ] Janela de manutenção agendada\n\n### Durante Migração\n- [ ] Backup do sistema atual\n- [ ] Dados importados com sucesso\n- [ ] Testes funcionais passando\n- [ ] Testes de carga passando\n- [ ] Testes de failover passando\n- [ ] DNS atualizado\n- [ ] Tráfego redirecionado\n- [ ] Monitoramento ativo\n\n### Pós-Migração\n- [ ] Todas as funcionalidades validadas\n- [ ] Métricas de performance normais\n- [ ] Alertas configurados\n- [ ] Documentação atualizada\n- [ ] Equipe treinada\n- [ ] Plano de otimização iniciado\n\n---\n\n## 📞 Suporte Durante Migração\n\n**Equipe de Suporte 24/7:**\n- Telefone: +55 (11) 3000-0000\n- Email: support@aquilapro.com.br\n- Chat: https://aquilapro.com.br/chat\n\n**Escalation:**\n1.
